# Cron prompt template

This file shows how to wire `feishu_task_card.py` into a scheduled job.

## Example: daily AI digest at 07:15

Add to your crontab:

```cron
15 7 * * * /usr/bin/python3 /path/to/feishu-task-card-pusher/scripts/feishu_task_card.py \
    /path/to/daily-digest.md oc_your_chat_id \
    --title "AI Digest $(date +\%F)"
```

Replace:
- `/path/to/feishu-task-card-pusher/scripts/feishu_task_card.py`
- `/path/to/daily-digest.md` — wherever your report generator writes its output
- `oc_your_chat_id` — your Feishu chat

## Example: agent-orchestrated daily digest

When the digest is generated by an LLM agent (e.g. inside a `cronjob`-driven prompt), instruct the agent at the end:

```
After you have written the markdown report to {report_path},
you MUST invoke the pusher to send it to Feishu:

python {skill_path}/scripts/feishu_task_card.py {report_path} oc_xxx \
  --title "AI Digest {YYYY-MM-DD}"

The pusher will:
- Read FEISHU_APP_ID / FEISHU_APP_SECRET from .env
- Build a 28 KB interactive card with all your sections
- POST to Feishu and return message_id on stdout

Do not attempt to call Feishu APIs directly. Do not use any send_message tool.
This script is the only correct delivery path.
```

## Why the agent must not improvise sending

The LLM in a cron context usually has no `send_message` tool exposed. Asking it to "send via Feishu API" produces hallucinated curl commands. The pusher is a self-contained Python script — no LLM, no agent loop, no guessing.
